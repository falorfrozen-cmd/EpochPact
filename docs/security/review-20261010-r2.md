# EpochPact feedback and security candidate — 10 October 2026

**Status: not cleared for player distribution.** Candidate
`0.1.1-alpha.2-review.2` fixes two reported defect paths and hardens generated
hook code. Fresh VirusTotal findings remain. They are not declared false
positives, and a zero-detection or malware-free claim is not justified.
The quarantined Nexus files and the earlier review candidate were not replaced.

## Changes and scope

- Auto pickup previously requested collection every 750 ms even while an item
  tooltip was being inspected. The new core pauses mod collection while
  `TooltipItem.highlightedTooltipItem` is alive, including a recheck before each
  pickup call. It keeps the original game tick running and resumes without
  consuming scan intervals during hover. Missing/unreadable hover state refuses
  or pauses collection. This matches the reported interruption mechanism;
  **a fresh live-game mouse-hover test has not been performed**.
- Installation compatibility reads previously converted `PermissionError`
  into a generic string, losing the explicit administrator-retry signal.
  Errors now retain their path/detail. Inaccessible downloaded mod files do not
  offer elevation; game-folder access denial can offer the separate existing
  **Install as administrator** action. The player's screenshot cannot identify
  whether ACLs, file locks or security software caused their E: drive denial.
  Elevation is not a solution to quarantine.
- Read-only Toolhelp process enumeration replaces spawning `tasklist.exe`.
  Enumeration failures block installation instead of assuming the game is
  closed. This follows the documented
  [Windows process-enumeration API](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-process32nextw).
- Each generated trampoline/relay is now built in its own RW page and sealed
  RX, with checked protection and instruction-cache flush before publication.
  Reinstallation does not rewrite active trampoline pages. This follows
  [VirtualProtect's instruction-cache requirements](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualprotect).
  Target-function patching still temporarily changes code protection; this is
  not a claim that all writable executable memory has been eliminated. The
  cause of antivirus detections is not established by this hardening.
- Native/app build tools accept isolated build directories. The old game-side
  binaries, published archives and review.1 artifacts remain byte-identical.
  Review.2 uses the unchanged review.1 loader and the newly built core.

The other requests are individually classified in
[the feedback triage](../feedback-20261010.md). Existing summoner stat aliases
do not establish arbitrary summon durations. Independent skill XP, point-budget
changes, tree bypasses, off-hand/set changes, overhead zoom, blessing controls,
extra projectiles and arbitrary item construction were not enabled or
advertised as working features.

## Remaining release blockers and next action

1. Request analysis from the responsible vendors using the exact files/hashes,
   public source, build provenance and reports. The
   [vendor-review draft](vendor-review-request.md) is ready but **not sent**.
   Do not silently alter binaries to chase detection counts, claim a false
   positive without evidence, or ask players to disable protections.
2. The required proxy loader still calls System32 `LoadLibrary` from `DllMain`.
   Moving forwarding initialization outside the loader lock needs a separate
   carefully tested loader change; it is not solved by RX trampolines.
3. Perform live tooltip-hover/resume and game shutdown measurements once the
   security review permits testing. Isolated native/API tests cannot substitute.
4. Resolve the existing Nexus quarantine and then verify the downloaded main
   file's hash. No Nexus clearance or successful fresh download is recorded.
