# Review.3: player feedback and native correctness follow-up

Version: `0.1.1-alpha.2-review.3`. This candidate is not a cleared player release.
The initial feedback fixes were pushed first in `4c3b8fa` to
`round1-xp-multiplier`; this follow-up records the subsequent native hardening.

## Fixed in source

1. **Unknown tooltip reads:** actual game accessors now return read success
   separately from a null object. Static/lifetime reads publish values only after
   a successful guarded call. Pickup pauses on unknown state; vanilla tick is
   preserved. `TooltipItem.highlightedTooltipItem` exists in the local supported
   1.5.2.1 metadata, but this does not prove the live mouse-hover semantic.
2. **Permission errors:** backend PermissionError is preserved; CLI OSError is
   shown as a short failure with exit code 2. Failed process enumeration blocks
   installation. Result files use SHGetKnownFolderPath rather than environment
   overrides, reject linked ancestors, recheck after installation and create the
   result exclusively rather than overwriting it.
3. **Loader initialization:** DllMain only records its module and disables thread
   notifications. First version calls use InitOnce and System32-restricted loading.
   Generic x64 thunks preserve register/stack arguments; the core thread owns a
   loader reference until completion. Crash-handler hosts do not start the core.
4. **Thread preflight:** snapshot enumeration, OpenThread, SuspendThread and
   GetThreadContext failures no longer get silently skipped. Two stable snapshots
   are required before suspension. Allocated buffers remain alive until after
   resumption; freeing them on Freeze's success return could wait on a suspended
   thread's heap lock.
5. **Patch transaction:** cache flush/protection restore failures are checked.
   Protection restoration gets bounded retries with the exact original flags.
   Failed writes restore previous bytes/cache/protection before resuming threads,
   and report whether rollback itself failed. No new claim of infallible recovery
   is made if the OS rejects every restoration attempt.
6. **Patch ownership:** installation/removal compare expected bytes while threads
   are held; removal refuses to overwrite a foreign patch. All unpublished failed
   trampoline pages are reclaimed with correct page-size allocation accounting.
7. **Shutdown:** after stopping/cancelling queued work and waiting for the command
   worker, the shutdown guard attempts to restore every owned hook before original
   IL2CPP shutdown. Immutable published trampoline pages remain allocated for
   callers already using them. Failures are reported rather than overwriting
   foreign code or unloading the core under active callers.

## Open limits and release blockers

- A real-game hover test is still necessary. If vanilla distant pickup itself
  dismisses a tooltip, preserving its tick does not fix that vanilla behavior.
- The previously observed full-game exit `0xC0000005` remains unresolved. Hook
  restoration reduces a teardown risk; a synthetic ordering test is not proof
  that the observed crash is fixed.
- The explicit administrator path still elevates a user-writable Python app
  tree. Output-path hardening does not resolve that architectural concern. A
  separate minimal trusted helper/secure installation location is still needed;
  the manual ZIP avoids having to elevate the app.
- Known-folder/junction/exclusive-result checks are not a universal atomic
  parent-directory-handle defense against a malicious concurrent local process.
- Stable preflight snapshots do not forbid new threads after the last snapshot.
  Lazy version resolution can still be called under another DLL's DllMain; do
  not generalize these fixture results to universal loader-lock safety.
- Antivirus detections are unresolved. Vendor clearance, code signing and live
  tests must not be inferred from successful builds, local scans or a low count.

The [official-source remediation research](av-remediation-20261010.md) identifies
vendor submission routes and signing eligibility limits. No vendor message,
signing subscription, license change or cleared release was published this turn.
