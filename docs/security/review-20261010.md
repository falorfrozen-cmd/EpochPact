# EpochPact security review — 10 October 2026

**Status: local review candidate, not cleared for distribution.** The reason for
the antivirus detections on Nexus files 251 and 252 remains unexplained. A clean
Defender scan is one result, not proof that every security product will accept
these files or that they contain no malware. The original archives are preserved.
The Nexus support request was sent; no approval or case resolution is recorded.

## Concrete changes

- Flask 3.1.2 → 3.1.3 fixes [GHSA-68rp-wp8r-4726](https://github.com/pallets/flask/security/advisories/GHSA-68rp-wp8r-4726).
  This session/cache vulnerability does not establish the cause of the antivirus
  detections. The reviewed application uses a loopback API; the advisory's
  exploitable deployment conditions were not demonstrated here.
- The new build environment uses wheel 0.46.2, fixing
  [GHSA-8rrh-rw8j-w5fx](https://github.com/pypa/wheel/security/advisories/GHSA-8rrh-rw8j-w5fx).
  wheel 0.45.1 was a proposed build dependency, not an installed dependency in
  the original build environment. Neither wheel nor setuptools is distributed.
- Resolve `tasklist.exe` through Windows' system directory rather than PATH or
  the current folder. Core DLL dependencies resolve beside the explicit core
  path or in System32; a same-named DLL on PATH/current directory is refused.
- Add an inspectable folder build: required Python/runtime files stay beside the
  application rather than being unpacked by a single-file EXE. This layout is
  [documented by PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html);
  it is not an antivirus bypass or guarantee of clearance. UPX remains disabled.
- Remove unused build/compiler tools and Android archive assets. Keep required
  WebView2/.NET interoperability files and the two game-side DLLs. ZIP validation
  rejects changed/unlisted files, links, case collisions, unsafe Windows names,
  nested archives, research builds and historical character snapshots.

## Repeating the review

Use Python 3.13 x64, MSVC x64 and the source/native player build prerequisites.
`requirements-build-win64.pins` and `.lock` identify the official PyPI inputs.
`tools.audit_build_inputs` fetches/verifies those inputs and compares installed
files without executing downloaded code. `proxy_tools` is an official source
distribution; its wheel is built locally with pinned build tools, not downloaded
as an official wheel. Bootstrap the pinned setuptools/wheel/packaging artifacts
before installing that source distribution with `--require-hashes`,
`--no-index`, `--find-links` and `--no-build-isolation`.

The isolated commands used for the candidate, from the repository root:

```powershell
native\build.bat loader build\security-review\native
build\security-venv\Scripts\python.exe -m tools.build_player --layout onedir --output dist/security-review/onedir-final --work build/security-review/pyinstaller-final --stage build/security-review/resources-final --loader build/security-review/native/version.dll --version 0.1.1-alpha.2-review.1
build\security-venv\Scripts\python.exe -m tools.verify_loader_security --loader build/security-review/native/version.dll
build\security-venv\Scripts\python.exe -m tools.package_review_bundle --bundle dist/security-review/onedir-final/EpochPact
```

Use a fresh output directory: the builder/packager refuses to overwrite existing
review evidence. This records build provenance, not a claim of bit-for-bit
reproducibility across toolchains. The candidate deliberately reuses the verified
original player core; building the loader does not rebuild that core. The compiled
installer test additionally needs a privately held supported `GameAssembly.dll`
fixture. That proprietary game file is not distributed.

## Remaining limits

- Old EXE/DLL detections and Nexus quarantine remain unresolved. No claim of
  false positive, new Nexus clearance or fresh multi-engine result is made.
- No new gameplay validation was performed for this candidate. The previously
  observed full-game exit `0xC0000005` is still a known issue.
- The loader still loads the absolute System32 `version.dll` inside `DllMain`.
  [Microsoft advises against LoadLibrary there](https://learn.microsoft.com/en-us/windows/win32/dlls/dllmain).
  Restricting core dependency search does not fix or certify loader-lock behavior.
- Matching official artifacts does not audit every upstream dependency's code,
  all local file ACLs, or the Windows/.NET installation. The binaries are unsigned.
- Nexus download/hash comparison cannot be completed while downloads are blocked.

Do not replace quarantined uploads or publish this candidate as an approved
release. Keep the originals for the existing review. Do not disable protection,
add exclusions, or conceal hooks/detections to obtain a lower detection count.
