# Player feedback triage — 10 October 2026

Security review takes precedence. Candidate `0.1.1-alpha.2-review.2` contains the
installation/auto-pickup fixes below, not the unimplemented feature requests in
this table. A successful test build is not a claim that these requests work in
Last Epoch. The currently uploaded Nexus files remain quarantined.

## Reported defects

### Auto pickup dismisses the hovered item tooltip

The current core calls the game's `GroundItemLabel.requestPickup` and the active
pickup lists every 750 ms. It previously did this even while an item was being
inspected, and could retry items which stayed on the ground. This matches the
reported repeating interruption; the report alone does not establish every
possible tooltip-closing cause.

The new core reads `TooltipItem.highlightedTooltipItem` by runtime metadata name.
It pauses mod pickup while that Unity object is alive, without blocking the
original distant-pickup tick or consuming the next scan interval. It checks again
before each pickup call. Missing/unreadable hover state pauses or refuses this
feature instead of collecting blindly. The interval remains 750 ms when there
is no hover. This does not claim to solve every full-inventory/retry case.

`items_test.exe` executes the real detour, snapshot traversal and managed pickup
invocation against controlled objects: 11/11 checks passed, including hover,
resume, original tick, offline gate, failed reads and a tooltip appearing midway
through pickup. This is a compiled fixture, not a new live mouse-hover test.

### Install mod reports only Permission denied (WinError 5)

The old compatibility check caught `PermissionError` as generic `OSError`,
returned a string, and lost the UI's explicit administrator-retry signal.
Process enumeration also launched `tasklist.exe`; a launch failure happened
outside the setup status error handler.

The new app preserves installation access-denied errors and their path/detail,
exposes **Install as administrator** only as a separate explicit action, and
distinguishes inaccessible bundled files from the game-folder installation path.
Unreadable process enumeration blocks installation. Process names now come
from a read-only Windows Toolhelp snapshot; no tasklist child process is started.

Source tests reproduce denied compatibility reads, denied bundled artifacts,
denied staging/publication with rollback, and process-enumeration failure.
The rebuilt EXE also passed the existing 17 isolated installation/API checks.
No real UAC click or the reporter's E: drive ACL was tested. The screenshot alone
cannot distinguish folder permissions, file locks and antivirus intervention.
An administrator retry is not a way to bypass quarantine.

## Feature requests

and locally held IL2CPP metadata. Finding a method name does not establish a
verified ABI, complete behavior or a shipping implementation. No speculative
hooks for these requests were enabled in the player build.

Recommended sequence after security review and live verification of the two bug
fixes: independent skill XP and camera zoom; point budgets/requirements; blessing
choices/projectiles; ability-specific summon controls; custom item workshop.
Point/save changes and arbitrary item construction require stronger rollback
and reload validation than temporary session multipliers.

## Security change in this candidate

Previously, generated trampolines remained executable **and** writable.
The new engine builds each trampoline/relay in a separate RW page, checks the
transition to RX and the instruction-cache flush, then publishes it. Reusing a
hook does not rewrite active executable pages; a different detour receives a
new immutable page, retaining old code for callers still returning through it.
The 50 hook-engine checks, including the concurrent install/remove test, passed.

This is legitimate hardening. It does not establish why any antivirus engine
flagged EpochPact. Function patching still temporarily needs writable code pages;
the proxy loader and the previously reported full-game exit issue remain review
items. Antivirus protection was not disabled and no exclusions were added.

See the [review.2 candidate report](security/review-20261010-r2.md) for exact hashes, scan results, test scopes and
release blockers. Unimplemented requests above are not advertised as features.
