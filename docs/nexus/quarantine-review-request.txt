What the package does
EpochPact is an unsigned native loader/core plus an external, bundled-Python desktop application for offline Last Epoch. The version.dll proxy loads the project's native core from the game directory; the core hooks supported game functions and processes offline commands. The desktop app uses a loopback interface and the existing local IPC. Both required DLLs are included in the manual package and embedded in the optional app. The desktop app is bundled with PyInstaller; users do not install Python. Windows x64, WebView2 and .NET Framework 4.8 are required. MelonLoader/BepInEx are not required.

Supported game: Steam Last Epoch 1.5.2.1, Steam build 25816319 (internal 1.5.2.2). Online is unsupported. Game compatibility is checked against the locally installed GameAssembly.dll before app installation/launch. No proprietary game executables, GameAssembly.dll, game metadata, saves, private logs, SDKs, test drivers or nested/encrypted archives are distributed.

Build on Windows x64 with Python 3.13.7 and MSVC x64 Build Tools (C++20, static /MT CRT):
git clone https://github.com/falorfrozen-cmd/EpochPact.git
cd EpochPact
git checkout e62d998df4fd2ee797698c923cc0309e2099c966
py -3.13 -m venv .build-venv
.\.build-venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\native\build.bat player
.\.build-venv\Scripts\python.exe -m tools.build_player
.\.build-venv\Scripts\python.exe -m tools.package_nexus_release --output dist/nexus-review

Use a new output directory. The package script refuses to overwrite an existing archive, uses an explicit allowlist and verifies each ZIP entry against its runtime manifest. This describes how to rebuild the project, not a claim of bit-for-bit reproducibility across toolchains/timestamps. The recorded build environment is in docs/nexus/build-environment.txt.
